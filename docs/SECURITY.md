# وضعیت امنیت کابل‌وب

## بررسی اولیه (چرخه فعلی — 2026-11-11)

### نقاط قوت
- فقط کلید publishable در کلاینت
- اجبار status=pending در insertها
- escapeHtml و بررسی URL ایمن
- چک ادمین با ایمیل + RPC is_kabulweb_admin
- SQL RLS آماده در docs/security_rls.sql
- Content-Security-Policy روی صفحه اصلی و صفحات حساب/مدیریت
- cooldown ساده سمت کلاینت برای فرم ثبت آگهی (60 ثانیه)
- فیلد honeypot در فرم ثبت آگهی برای شناسایی ربات‌ها (اضافه شده در این چرخه)

### اقدامات فوری مالک (بدون این امنیت کامل نیست)
1. اجرای کامل docs/security_rls.sql در Supabase SQL Editor (اگر هنوز انجام نشده)
2. تأیید وجود دو حساب مدیر در Auth
3. تست کاربر عادی نتواند داده approved بخواند یا ویرایش کند
4. بررسی منظم لاگ‌های Supabase برای فعالیت‌های مشکوک
5. (پیشنهادی) ایجاد جدول security_events برای ثبت رویدادهای مشکوک و فعال کردن هشدار

### محدودیت‌ها
- سایت استاتیک GitHub Pages → مانیتورینگ خودکار ۲۴/۷ و دفاع DDoS پیشرفته ممکن نیست (فقط امکانات میزبان و Supabase)
- Rate limiting سمت سرور وجود ندارد (فقط سمت کلاینت + سیاست‌های Supabase)
- هیچ سیستم ثبت گزارش امنیتی خودکار فعال نیست

### اقدامات این چرخه
- افزودن فیلد honeypot مخفی به فرم ثبت آگهی و بررسی آن در script.js (رد ساکت ارسال‌های ربات)
- به‌روزرسانی مستند امنیتی

## چرخه بررسی و تقویت امنیت (2026-11-13)

### وضعیت فعلی کد
- مرور کامل کد اصلی (index.html, script.js, js/supabase.js, admin/account pages) انجام شد.
- هیچ آسیب‌پذیری حرجانی جدید در کد کلاینت مشاهده نشد:
  - استفاده منسجم از escapeHtml برای جلوگیری از XSS
  - بررسی isSafeHttpUrl برای لینک‌ها و تصاویر
  - اجبار status="pending" در تمام insertهای عمومی
  - honeypot فعال و بررسی‌شده
  - CSP محدودکننده منابع
  - cooldown کلاینتی 60 ثانیه‌ای

### اقدامات این چرخه
- بررسی وضعیت امنیتی و تأیید نقاط قوت موجود
- به‌روزرسانی مستند با یادآوری اقدامات مالک
- هیچ تغییر کدی بدون آزمایش منتشر نشد (این برانچ برای مرور است)

### یادآوری مهم برای مالک
بدون اجرای docs/security_rls.sql در Supabase، سیاست‌های Row Level Security فعال نیستند و حمایت از داده‌ها ناقص می‌ماند. لطفاً این کار را انجام دهید و تست کنید.

برای ثبت رویدادهای مشکوک، پیشنهاد می‌شود جدولی مانند security_events در Supabase ایجاد و از Edge Function یا لاگ‌های موجود استفاده شود. مانیتورینگ خودکار ۲۴ ساعته فعلاً نیست مگر اینکه سیستم خارجی متصل شود.

**هیچ‌وقت ادعا نمی‌کنیم سایت را ۲۴ ساعته محافظت می‌کنیم مگر سیستم مانیتورینگ واقعی فعال و متصل باشد.**
